# 按任务与页面选择设计方法

用于新建、多屏铺开、存量改版或领域混合的任务；小修改只取相关规则。这里将 Oil UI Pro 的范围分流、领域骨架、代表页与证据评审方法改编为 APP UI Studio 的自包含流程，无需安装或调用 Oil。来源见插件 [NOTICE](../../../NOTICE.md)。

## 范围先于审美

| 用户目标 | 允许变化 | 先做什么 | 验收基线 |
|---|---|---|---|
| 明确的小修改 | 指定元素与必要的相邻调整 | 直接复用现有组件与变量 | 相关行为；样式变更看目标视口 |
| 新建 | 要求的页面、任务与状态 | 推荐一个方向、固定导航和代表页 | 需求、真实渲染与操作 |
| 存量精修 | 层级、密度、对齐、语义样式 | 同状态基线、定位共享样式根因 | 已确认规范及前后对照 |
| 改流程或加功能 | 获准的入口、步骤、对象和状态 | 走现有路径，核对 API、保存与恢复 | 原流程回归及新增路径 |
| 原型落地或截图还原 | 参考决定的可见设计、必要状态 | 参考元素 → 现有组件/变量的映射 | 同视口、数据、状态下的并排图 |
| 只读审查 | 建议与证据 | 区分可见事实与待验证推测 | 当前证据能支持的结论 |

先读本次相关路由、tokens、组件和一两页同类实现；新旧规范并存时查实际使用处与变更记录。缺 DESIGN.md 不代表项目可以重做。精修不改业务流程；加功能沿用视觉系统；只有获准重塑的部分才重新选择视觉语言。

默认推荐一个适合产品的方向。用户明确要比较时才提供多个候选，候选保持相同任务、内容和锁定项，比较结构与层级，不只换色。`compare` CLI 仍只检查冻结证据的可比性，不生成设计候选。已有方向、用户说“你定／直接做”或已授权实施时继续完成；缺失信息会改变核心业务、权限或高代价决策时才问。诊断结论不能自行扩大范围。

## 按每页的任务选择领域

软件类型描述能力，行业描述语境，页面领域决定构图。同一产品可以包含以下多种页面，SaaS 或“App”不自动意味着仪表盘。

| 页面主要任务 | 领域 | 骨架与检查重点 |
|---|---|---|
| 反复处理对象、配置与状态 | workspace 工作区 | 按任务选列表/表格、队列+详情、分组表单或编辑画布；对象、判断依据与动作相邻 |
| 浏览、发现、挑选与阅读 | content 内容浏览 | 内容对象先出现，按识别属性选网格、列表或索引；筛选贴近内容；从详情返回保留位置 |
| 了解价值、判断适配与采取行动 | persuasion 说服页 | 先选符合内容的整体构图，再安排标题、证据与 CTA；产品画面须可辨，不默认左右分栏或卡片拼盘 |
| 操控、计时与即时反馈 | play 操作体验 | 核心操控、规则与状态优先；暂停、结束和恢复按玩法需要设计；键盘/触控均有可达路径 |

工作区：区分全局导航、组织/项目范围与对象内 Tab。列表留下决定是否处理对象所需的字段，低频证据进入详情。数字使用一致单位、精度和 `tabular-nums`；指标、明细和筛选计数口径一致。表面、文字、边界、焦点、强调色、状态色各有语义，不因字段多就层层套卡。

内容浏览：先定义一个内容对象的图、名称、关键属性、长名称和缺图状态，再铺集合。首屏检查能看见多少可判断的完整对象；品牌与标题按识别需要安排，不用海报挤掉内容。预览关闭后保持筛选、选中与滚动位置，触屏核心功能不依赖 hover。

说服页：明确受众、价值、可信证据和有效行动目的地；选定的构图节奏贯穿整页。素材承担信息或情绪时先确定素材，再排文字；已有真实产品截图优先复用。不能新增无依据的客户、认证或效果数据。动效表达内容关系，按需求和性能预算使用，不为过清单强制特效。

手机页面使用自己的导航与层级，不能把桌面侧栏、宽表格和多栏网格整体缩小。按实际任务选择底部标签、栈式详情或面板；顶栏避免重复品牌、标题与说明。主要动作、软键盘、安全区和长内容共同实测，原生尺寸仍按平台单位核对。

## 先验证代表页，再铺多屏

多页任务在编码前把现有屏幕矩阵补成页面地图：`页面 → 领域 → 入口/完成/返回 → 沿用哪张代表页 → 状态`。锁定本次全部页面的导航外壳，不做完单页后才发现其他页面无入口。单组件或小修改无需补整套地图。

1. 先做覆盖主要任务与最高风险状态的代表页；领域不同且不能共享骨架时分别选代表页。
2. 实际检查代表页的整体、原尺寸局部、主要路径及一个关键失败或边界状态。根据证据修正后再复用。
3. 将重复的导航、控件、对象行与反馈收进项目已有共享组件，取值收进现有 token 机制；单次出现的组合不预建框架。
4. 按页面依赖分批铺开；每批在相同目标视口看同类页面，核对导航、标题、密度、按钮、对象样式和窄屏变化。共享变更复看其他使用处，修根因而非逐页覆盖。

原型落地时，映射表注明“直接复用／现有变体／新增组件／必要依赖”。项目导航与工程边界保留，参考的视觉差异通过语义变量与组件变体实现；整屏图片、iframe 或整段原型脚本不能替代真正接线的页面。

## 设计规范保持一个事实源

需要整理或扩展规范时，按需读 [design-system.md](design-system.md)。从参考分析提取语义角色和组件关系，关联项目代码与证据；第三方品牌值、营销规则和未观察状态不自动写成产品约定。

优先原地使用现有 DESIGN.md、设计系统或等价载体，核对它与代表页、tokens 是否一致；冲突标明来源与影响，按当前用户决定和可验证现状处理。用户确认、代码观察、Agent 提案分别标注，不把偶然的组件库默认样式写成品牌要求。

多页需要持续共享规范时，记录必要的语义角色、组件、导航、代表页与例外；新方案尚未确认的内容保留为提案。单次小修改或只有一个独立页面时，在最终交付简述即可，不自动创建新的 DESIGN.md、报告或日志。

## 失败与结果未知

用户动作的反馈区分处理中、已成功、已失败和结果未知。超时不自动等于失败；有外部写入、批量或重试动作时核对查询回执与幂等契约。部分成功保留逐项结果、选择范围与上下文，只对可安全重试的失败项提供恢复，不能重复执行已成功或仍未知的动作。没有接口支持时说明限制，不伪造成功。

截图证明画面，实际操作证明可达流程；保存类操作还需刷新或重新读取。视觉与操作的分层评审及停止条件见 [quality-handoff.md](quality-handoff.md)。
