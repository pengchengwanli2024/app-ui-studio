# 默认设计与质量流程

用于新界面、改版、UI 精修和前端质量优化。默认优先使用实际可读的 Oil UI Pro 进行设计判断，以本插件已有的方法补齐工程与验证；用户当前要求、项目规范和现有授权优先。纯后端、文案替换、数量调整或复用现有样式不启动完整流程。

## 读取顺序与缺失处理

APP UI Studio 已在编排当前任务时，由它持有范围、阶段、问题清单与证据；组合入口只补充当前阶段。两个入口共存不启动两轮设计或审计，也不互相卸载。组合入口决定配套职责与调用顺序；默认 Oil 是设计负责人，用户明确选用其他设计者时本轮以该选择替代，不在之后再用 Oil 重开方向。

1. 优先读取宿主提供的 `ui-design-quality/SKILL.md`；没有清单但能访问文件时，检查 `$CODEX_HOME/skills/ui-design-quality/SKILL.md`（若设置）与 `~/.codex/skills/ui-design-quality/SKILL.md`。这是组合入口，按本次问题加载资源，不通读全部配套技能。
2. 读取实际安装的 `oil-ui-pro/SKILL.md`。宿主明确选定的版本优先；清单未显示时仍检查文件，先 `~/.agents/skills/oil-ui-pro/`，再 `$CODEX_HOME/skills/`、`~/.codex/skills/`、`~/.claude/skills/` 下的同名目录，去重后取实际可读版本。找不到或无法读取时说明情况，继续使用 [design-craft.md](design-craft.md) 和项目规则；不自动安装或复制 Oil UI Pro。
3. 按当前问题加载下表中的已安装技能或本插件参考。`doctor` 可以列出候选、可读性与哈希；文件存在或读过入口都不等于宿主启用、模型执行或验收通过。同名技能不静默混合。

| 当前问题 | 配套方法与适用边界 |
|---|---|
| 外部视觉参考、DESIGN.md 参考库、整理设计规范 | 已安装 `website-to-design-md/references/design-md-library.md`，或 [design-system.md](design-system.md)。区分宣传页与工作区、第三方分析与本次观察，映射到现有语义 Token/组件；不自动写新规范或采用品牌资产。 |
| Web 实现、兼容性、语义、布局或性能决策 | 已安装 Modern Web Guidance 的当前入口先 search/retrieve；`modern-web-guidance-source/references/web-quality.md` 提供源码追溯，或读 [modern-web.md](modern-web.md)。编译指南决定当前兼容建议；源码 demo/expectations 只提供检查依据。 |
| 实测审计、性能修复或质量回归 | 读取实际安装的 `lighthouse/SKILL.md`。先确认 URL、状态和模式，再留基线、修复、同条件复测。普通样式小改不强制全站审计；原生设备不由 Lighthouse 验收。 |
| 去模板化诊断或已确认方向的局部精修 | 按组合入口读取 `ui-design-quality/references/unslop-refinement.md`，只把观察到的问题交给当前设计负责人，在同一实现中处理。该本地参考不等于完整上游 unslop 流程；不可读时沿用本插件的组件精修与回改方法。 |

Windows 使用宿主报告的用户目录与已安装 Python；`~` 表示用户目录，不要求某个用户名或磁盘位置。无文件系统时遵循可访问的本插件参考，明确外部增强未读取；不因技能缺失停止独立可完成的工作。

## 将设计判断连接到实际结果

按组合入口的当前阶段推进：范围与取证→需要时在修改前留基线→设计或延续已定方向→相关客户端改动前取得实现指导→在同一实现中精修→共享验证→一次交付。独立的网站提取、源码或 Lighthouse 技能只执行分派阶段后返回，不重新从第一步跑。已有同版本/同状态证据仍有效时复用；最新修复只重验受影响的画面、操作与检查，原始比较基线保留，复测使用新标签。

先查看相关工作树、设计规范、Token、组件和真实入口；明确改哪里、保留什么、目标端与成功条件。沿用品牌和已确认方向，默认深化一个方向。用户已授权实施时连续完成适配与验证，专项建议不扩大任务范围或要求重复确认。

在所属组件与共享变量中修改，按风险运行项目已有 lint、类型检查、测试和必要构建。明确的小修只验证改动与相邻布局；只读评审不写文件；只要方案时不实现。设计、业务行为、保存读回与自动检查分别核验，不把生成提示词当作完成项目。

在实际目标视口看图，并从真实入口操作受影响的正常、拒绝与恢复路径。检查可见名称、键盘焦点、长内容和窄屏；表单失败应有对应字段状态、可理解的说明及可继续操作的位置，修正时清除过时错误。初始空白字段不提前报错，不能只用成功路径或自动评分代替这些检查。

性能相关比较固定页面/数据状态、构建、浏览器/工具版本、设备、节流和缓存策略；需要稳定结论时串行重复并保留波动。Lighthouse 的高分不证明弹窗错误状态、业务完成、审美、真实用户 INP 或完整 WCAG 达标。按 [quality-handoff.md](quality-handoff.md) 交付实际证据与未验证项；缺少工具时不补造结果。

这是对用户默认流程的独立适配，连接既有 Modern Web Guidance、源码、Lighthouse 与 awesome-design-md 方法。未捆绑外部技能正文或运行时，不改变宿主个人配置；后续以实际安装版本和当前项目事实为准。
