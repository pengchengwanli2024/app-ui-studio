# 宣传页、落地页与推广素材

由 `marketing` 或自然语言进入；本流程是文章方法的扩展。沿用项目品牌、tokens、真实功能与素材，不要求用户先做完整 APP。用户只要方案/提示词时止于相应成果；要求制作时交付对应实际产物。制作文件不自动授权上线、投放或提交应用商店。

## 先确定交付面

| 目标 | 产物 | 必查 |
|---|---|---|
| APP 落地页 / 官网宣传页 | 可运行页面、独立素材、桌面与手机截图 | 真实文案、主行动、响应布局、键盘操作、下载/预约路径 |
| 海报 / 社交宣传图 | 按已知渠道规格输出的图片与可编辑源（如要求且工具支持） | 字体与文字、画幅、安全留白、品牌和素材权利 |
| 应用商店截图 | 基于真实版本屏幕的系列素材与说明文案 | 屏幕真实性、平台最新规格、宣传语可证实 |

未确定的渠道和尺寸可在 brief 中标假设并制作可回退草稿。需要正式导出或提交到具体平台时核对当前一手规格，不凭记忆写死商店尺寸和审核承诺。

## 品牌到页面

1. 收敛为一个受众、一个场景、一个核心承诺和一个主要行动；读取已确认产品事实。没有证据的销量、评价、评分、获奖、客户 logo、价格和承诺不编造。
2. 建立内容顺序：首屏说明价值并展示真实产品 → 按任务说明能力 → 用确有证据的演示/案例支撑 → 回答实际疑问 → 行动入口。结构随内容调整，不强制堆满同款卡片或凑章节。
3. 从 APP 复用 tokens、IP、字体与已完成屏幕，营销画面允许更有表现力；手机模型中的实际 UI 仍使用真实截图，概念界面明确标为概念。主标题、按钮与重要信息在网页里保留 HTML 文本，不能把整页图片当网页交付。
4. 按 [integrations.md](integrations.md) 读取所需技能：UI/UX Pro Max 提供匹配当前产品的设计系统/landing 参考；Taste 承担整体艺术指导与版式；Impeccable 使用适用的 Persuade 页面模式，按任务加载 landing 参考或 audit / polish playbook。Mobile 约束手机端可读性、触控与导航；APP 操作页保留自身平台规则。
5. 需要主视觉时按 [media-tools.md](media-tools.md) 生成或编辑。图像与代码共享同一 brief；先做高影响的主视觉与首屏，再按实际差距迭代。不为宣传页重画已确认 APP 屏幕。
6. 使用项目原技术栈实现。下载/购买/预约按钮连接已知真实目的地；未提供链接时在本地草稿明确标为待配置，不伪造成功反馈或真实留资后台。

## 最终检查

网站至少核对项目要求的手机和桌面尺寸、长中文、图片裁切、焦点可见性、主行动和所有实际链接。表单验证用真实可执行链路；模拟提交标明模拟。检查最后一次修改后的渲染。海报检查实际导出尺寸、文字和裁切；商店截图检查真实屏幕与规格依据。

交付产物、来源与素材清单、实际截图、已验证操作、待配置目标和未执行阶段。宣传图可视化通过不证明 APP 功能通过；本地页面验证不证明已部署、已投放或商店已审核。
