# 组件深度打磨

用于明确要求精修单个控件、数据组件或操作面板的任务；范围与页面领域仍由入口决定。只调一个已指定的颜色或间距时直接局部修改，不执行本专项全流程。

## 从问题拆到可检查的部件

用用户的话写出组件回答的问题、主要动作、承载尺寸和输入方式。把组件拆成实际存在的触发器、值表达、选项行、选中标记、辅助说明、反馈和浮层；检查各部分的职责，避免同一个数值或操控重复出现。

先复用项目组件及其键盘/焦点行为，再调整语义变量和已有变体。工作区控件以识别和操作为准：状态选择器无需另造实物主视觉、插画、数字滚动或新的品牌母题。品牌展示、游戏或表现性组件确有需要时，才设计有辨识度的形状、图像与操作呼应。

在组件实际使用的密度下建立一小组 specimen，而非脱离页面无限放大：

| 比较单元 | 看什么 | 操作什么 |
|---|---|---|
| 触发器与当前值 | 行高、基线、长名称、图标、单位和空值 | 点击、键盘聚焦、触控命中 |
| 展开内容 | 选项分组、选中与焦点的区别、滚动和遮挡 | 打开、移动、选择、取消、返回触发器 |
| 状态与反馈 | 必要的加载、禁用、失败、未知及边界 | 快速反复操作、失败恢复、写入后读回 |

只列真实存在的状态，不为普通菜单补暂停、计划中等无关状态。主动作对数据或图形的影响应同步可见；业务结果仍以真实回执为准，不能由动画完成触发成功。

## 选一种，磨细它

方向已定时只深化当前方案。组件结构确有可选做法时，可先做少量静态内部试样，比较信息表达、动作位置与操作方式；只有用户要求比较时才把多种方案交付。不因深磨要求重设计整页。

选定后检查默认、关键边界和最高风险状态，再看展开/收起、连续输入和反向操作。拖拽存在时，指针、目标值和可见结果保持同步；吸附、阻尼与弹性只在有任务价值时使用。相关节奏与清理见 [motion-scroll.md](motion-scroll.md)。

表现性组件可把位图、数据标记和背景分层：身份与材质交给素材，精确数值、操作与实时状态由代码呈现。遮掉文字后检查图形是否表达变化可以帮助诊断，但不以此替代文字标签、语义和可访问性，也不把它设为数据控件的统一门槛。

## 证据与交付

保留原尺寸局部、组件所在页面和必要状态对照；需要看细部时补放大图。静态图只能证明几何与画面，手感需正常速度实际操作或可播放的记录。样例状态切换放在演示外壳里，不把测试按钮混入产品流程。

共享控件变动后，复看一个其他使用处与相关焦点/长内容状态。已有方向与正常行为没有退化、主要问题得到解决后停止；没有可见收益时不为固定评分或轮数继续。只有用户要求展示图时才额外制作作品图。
