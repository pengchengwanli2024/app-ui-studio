# 科技视觉语言：适用于 APP、SaaS 与宣传页

当用户指定“科技、酷炫、未来感、AI 智能体界面”，或显式选择 `tone=tech-refined/tech-expressive` 时按需读取。这是视觉方向，不替换产品领域、用户任务、已有品牌或原技术栈；普通任务不会仅因安装插件就切换风格。

## 可直接复用的描述

> 采用精密、现代、具有空间层次的科技设计语言。通过清晰网格、精致字阶、品牌光场、语义数据流和细致交互反馈形成辨识度。产品工作区保持稳定、可读、高效；营销首屏和品牌展示区可加强纵深、局部 3D、光感材质与有目的的动态演示。所有效果对应具体对象、关系或用户动作，统一到设计 tokens，并提供减少动态效果、静态素材和低性能降级。用真实产品内容和状态支撑画面。

`tech-refined` 强调精密和细节，适合长期工作的产品界面；`tech-expressive` 加强展示区的空间和动态表现。用户已有浅色或其他品牌风格时，将科技表达映射到原有颜色、表面和组件，不擅自改成暗色。

## 从真实产品对象提炼视觉机制

| 产品对象 | 视觉和交互实现 | 真实性边界 |
|---|---|---|
| 智能体任务与工具调用 | 步骤轨迹、节点关系、状态流转、可展开的调用与结果 | 连接实际状态；原型数据明确标记，不伪造后台执行 |
| 数据处理与分析 | 流向、范围、更新位置与关键结论的清晰编码 | 数值、单位、时间窗与来源一致，动画不捏造增长 |
| 品牌或抽象能力 | 有目的的局部光场、材质、深度或 3D 主视觉 | 放在指定展示表面，不能遮挡正文或控件 |
| 用户操作 | 精细的按压、焦点、选择、展开、等待、完成和错误反馈 | 每种动效说明状态变化，触屏不依赖 hover |

先声明效果落点，再写实现参数：表面/对象、触发条件、颜色角色、层次、时长/缓动、性能预算、静态降级和验收方式。参数是本次设计选择或项目既有值，不能冒充测量结果。科技感无需叠加所有效果；同一表面保留清楚的主视觉机制。

用户明确要求的光场、渐变、透明材质或局部 3D，可以覆盖 Taste/Impeccable 通用去装饰偏好；例外只针对已选择表面和效果。加载实际版本规则，检测器需要白名单时使用其真实支持的配置并记录理由，不编造 flag 或全局关闭检测。平台惯例、可访问性、减少动态效果和产品任务保持约束。

需要图像素材时沿用 [media-tools.md](media-tools.md)，需要 SaaS 项目编排时读取 [saas-mode.md](saas-mode.md)。图像生成、组件实现、最终渲染和交互分别留证，不把效果描述当作已制作成果。
