# SaaS 模式

入口：`$app-ui-studio saas`。仅在用户选择 SaaS 方向或任务明确需要时读取；不改变其他模式的默认行为。目标是专业、高级、精致、友好且符合真实业务的产品与营销体验，不生成无需求支撑的通用仪表盘。

## 参数与范围

- `scope=auto`：读取实际项目后选择 new / existing / mixed，不能因缺 DESIGN.md 就判断为新建。
- `scope=new`：按真实产品任务建立结构、tokens 与组件；缺少产品事实时先完成不依赖该事实的工作。
- `scope=existing`：读取现有路由、组件、品牌、数据和状态，默认保留已确认信息架构及关键操作。发现结构问题先给出定位、理由与影响，不能借精修偷偷改动。
- `scope=mixed`：新增与现有表面并存；先说明哪些复用、哪些新建，以及共享导航、状态与 tokens 的边界。
- `tone=tech-refined`（SaaS 默认）：科技精致。以清晰网格、克制品牌光场、细致材质和反馈建立现代感，工作区仍以阅读与操作为主。
- `tone=calm`：低刺激、平静专业。依靠比例、留白、字阶与稳定状态表达品质，适合长时间工作。
- `tone=tech-expressive`：更鲜明的科技表达。可加深空间层次、动态数据流与局部 3D，但限定具体表面和资源预算。

未指定 scope 时从项目事实推断并说明；tone 是可调整的方向，不意味着必须暗色、渐变、玻璃或 3D。真实平台和项目技术栈优先，不固定框架、字体或图标供应商。

`surface=product/marketing/both` 选择产品界面、宣传页或两者。只选产品时不自动增加官网；只选宣传页时不强制实现整套 SaaS。可用 `studio.py preset saas --scope existing --surface both --tone tech-expressive` 获取本地配置草案；它不读取或修改真实项目，也不生成图。`studio.py init --mode saas --output <新目录>` 可创建 brief、配置与交接模板，已有目标拒绝覆盖。

## 同一品牌，两种表达强度

| 表面 | 优先任务 | 表达边界 |
|---|---|---|
| Operate 产品工作台 | 看清信息、完成任务、理解状态、恢复错误 | 稳定导航、合适密度、明确主次；装饰避开表格、表单、编辑区与关键状态 |
| Persuade 营销页面 | 理解价值、判断适配、采取行动 | 可扩大字阶、留白、品牌光场与宣传 KV；产品展示和商业事实必须有来源 |

共享语义颜色、字体家族、间距尺度、圆角逻辑、图标语言及状态含义；通过有明确用途的表面变体调整密度、字号、材质与动效强度。不要为了完全一致把营销页压成工作台，也不要把营销演出搬进高频任务区。记录映射到项目现有 tokens，不新建冲突的事实源。

## 四技能共同设计

按 [integrations.md](integrations.md) 发现并读取实际版本，不把名称出现当执行证据：

| 技能 | SaaS 中的完整职责 |
|---|---|
| UI/UX Pro Max | 任务、信息架构、设计系统、色彩、字阶、图表与相关技术栈研究；用真实场景核对建议 |
| Mobile App Design | 按实际平台审查导航、触控、键盘、缩放、读屏、响应式与性能；原生遵守原生规范 |
| Taste | 在当前安装版适用范围内承担艺术指导、构图、布局、密度、视觉语言、实现与截图迭代，不限于上色；若该版明确排除多步骤产品UI，产品侧结合项目契约与Mobile规范，不能虚报Taste已运行未支持流程 |
| Impeccable | 技术与 UX 审查，以及布局、文案、状态、动效、无障碍和最终精修；修正有证据的差距 |

结构未确认时，四技能可共同提出布局方案；结构已确认时，布局能力用于提高该结构的清晰度。需要改变导航、任务顺序、核心分区或操作契约时，显式提交变更与影响，按当前授权处理。不能轮流覆盖设计方向或以通用偏好删除已选品牌表达。

用户明确要求的科技美学优先于 Taste/Impeccable 通用去装饰偏好。例外要落到具体表面，例如“营销 hero 背景的品牌光场”或“运行详情中的状态流向”，并说明目的和降级；不扩大成全站装饰豁免。平台惯例、可读性、对比度、动效降级和性能仍需满足。

## 把科技感转成实现约束

通用科技描述和 AI 智能体状态表达见 [tech-visual-language.md](tech-visual-language.md)。下表用于 SaaS 表面的具体落点，不要求每个表面同时叠加所有效果。

| 手段 | 可执行方式 | 检查点 |
|---|---|---|
| 空间层次 | 用表面、边缘、阴影与少量透明层区分导航、内容和浮层 | 阅读顺序清晰；透明叠加后仍有足够对比度 |
| 品牌光场 | 在指定背景或品牌素材上使用受控色彩与光照，前景文字独立渲染 | 不遮挡内容；浅深主题均检查；静态降级可用 |
| 语义数据流 | 仅依据真实关系与状态表现方向、阶段或更新 | 不伪装实时；颜色之外仍能理解；暂停后信息完整 |
| 细致反馈 | 以焦点、按压、加载、完成和错误反馈解释用户动作 | 支持键盘、触控；尊重 reduced motion；失败可恢复 |
| 可控 3D / 粒子 | 限定 hero、品牌展示或必要空间表达；设置复杂度、加载与暂停策略 | 不占满任务区；按目标设备测性能；无 WebGL/低性能时用静态素材 |

动效与素材预算根据实际设备和现有项目要求设定并记录；未测量不宣称达标。科技表达不能靠全屏循环光效、无意义数值或随机粒子堆叠。

## 素材必须进入交付链路

需要 UI 视觉、品牌素材或宣传 KV 时，执行 [media-tools.md](media-tools.md) 的 Lovart 与当前图像工具协议，而不是只列工具名称：先锁定 UX / tokens / asset plan → 实际生成 → 筛选、下载并保存到可用项目位置 → 接入真实组件 → 渲染、对比与交互验证。工具分工、素材输入和结果证据以该协议为准。

素材计划应给出用途、目标表面、尺寸/比例、透明需求、组件落点和验收方式。生成图可提供品牌材质、插画、产品视觉与 KV；按钮、文字、输入、导航、数据和交互仍由真实组件实现。素材不匹配时修订或保留已有合格素材，不用任意图片填坑。

无工具、无额度或缺少必要费用授权时，准确标记相关步骤 `not_executed`，保留可复用提示词并继续布局、tokens、组件与状态等独立工作；不为展示流程擅自购买或产生未授权费用。

不得编造客户数、实时 agent 数、营收、认证、客户 logo、评价、产品能力或线上成功状态。原型确需示例数据时明确标记，并与真实业务数据分开；未提供的商业证明不制作成可信背书。

## 可观察的完成标准

依据本次要求验收：任务与 scope 对齐；Operate/Persuade 的 tokens 映射一致；实际组件和关键状态可用；要求的素材已生成、保存并接入；目标尺寸已渲染并对比；关键路径已操作。沿用 [quality-handoff.md](quality-handoff.md) 的证据与交接规则，分别标记 `verified`、`partial`、`not_executed`、`needs_input`。提示词任务交付于可直接使用的提示词，不能宣称执行了其中的制作流程。
