# 图像方向、图标与设计稿校准

本文件由mockup、icon-set、visual-explain、art-direction按需进入；只使用命中部分。来源版本和处理方式见 [oil-ecosystem.md](oil-ecosystem.md)。

## 设计稿与实现之间先校准单位

先分清借鉴风格、出稿、精确还原，以及完整页面或局部裁切。记录位图实际像素、是否完整画布、目标逻辑视口与已知导出倍率；1536像素不自动等于1536 CSS px，也不能据此推定DPR。只有确认两张是同一完整视图时，才按对应宽度映射几何关系。

优先核对导航、主体边界、栏宽与关键对齐线，再处理字阶、间距、素材裁切和细节。字体、触控区、安全区和平台组件不随整图机械缩放。保留原参考，测量或屏蔽固定区域时使用副本；概念图中的字和控件还原为真实组件。

小程序沿用当前框架、布局单位、rpx基准与原生组件，不把浏览器手机宽度当作小程序验收。分别记录H5预览、开发者工具与真机结果，实测长中文、返回、键盘、滚动和安全区；没有对应环境就标未验证。

查看媒体优先使用宿主直接读取原图；确需辅助识别时保留文件身份、裁切和任务范围。多图对比应联合观察同状态原图，OCR只表示文字识别，不证明完整布局、颜色或交互；辅助模型输出是待核验证据，不能替代原图或改写用户要求。无需为了看图更换主模型、注入上下文Hook或改全局设置。

## 成套图标的生产与检查

先确定每个真实栏目/动作的语义、隐喻、文件名、目标尺寸与使用位置。品牌栏目或奖励图标可以用统一位图；小尺寸、高频工具栏优先复用现有矢量体系，不整站替换成装饰图。

把网格、线宽、圆角、透视、光向、色板、细节预算与公共部件写成简短构造约定。数量按任务决定，不因上游模板的固定宫格增加项目功能。批量生图存在时，提示词明确行列、逐格顺序和空格；拆分后逐项检查邻格碎片、主体完整度、真实alpha和命名映射，不能把整张宫格当可用产物。

同一外框尺寸不代表同一视觉大小：圆形、细长形和密集形要在实际栏目中核对光学比例、对齐与辨识度。分别放到浅/深背景看边缘、残色与裁切。只在工具、预算及授权可用时实际生成或编辑；缺少时交可执行方案与待制作项，不自动另起CLI、安装抠图环境或切换收费服务。

批量结果保留输入项、提示词/参考、输出文件和实际状态的对应关系；预览顺序不能冒充生成顺序，失败项不能用下一张结果顶替。外部回执到文件接入分别核对，预览中的用户文本按数据转义。认证或来源问题先定位，不盲目重复提交同一批付费任务。

## 解释图与独立插画是不同交付

解释图要独立说明关系：用对象、路径、数量、状态或对照呈现证据，标签只帮助识别。可复用插画则把主体与背景分离，标题和说明交给外层排版；应用内的交互信息仍是可访问文本。独立分享位图中的文字需逐字检查。

视觉语言从项目品牌与内容推出。上游的角色、漫画风或固定色板是其具体方案，不是APP UI Studio默认皮肤。人物或装饰只有帮助当前信息时才使用，不复用未获授权的身份素材，也不让生成图冒充真实产品或事实证据。

## 从语境形成方向

地域、材质、生产过程或用户环境可作为构图参考，写清它和产品任务的联系；不是套城市名、纹理和非标准导航。选定方向贯穿内容层级、主体与行动区，仍满足阅读、导航与低动效要求。现有品牌锁定时只改变获准部分；工作区继续使用任务骨架，多方向规则见 [exploration.md](exploration.md)。
