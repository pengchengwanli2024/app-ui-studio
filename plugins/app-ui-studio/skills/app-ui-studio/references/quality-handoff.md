# 质量检查与交接证据

最低基础规则可独立使用；有外部技能时按其对应表面补充，而非重叠跑完整流水线。

| 维度 | 检查 | 证据边界 |
|---|---|---|
| 任务与结构 | 主要动作清楚、导航与返回可预测、层级和跨屏一致 | 屏幕矩阵与实际操作 |
| 品牌与视觉 | 一致 tokens、真实字体回退、图标统一、IP 轮廓与姿势对应 | 同尺寸参考与实际截图；alpha 检查 |
| 可访问性 | 普通文本对比度 ≥4.5:1；大文本 ≥3:1；需要识别的控件/图形通常 ≥3:1；不只靠颜色 | contrast 计算需用实际渲染色，半透明先合成；脚本不证明全部 WCAG 合规 |
| 触控 | iOS 44×44pt、Android 48×48dp；Web 以实际平台和可达性要求检查，通常以44 CSS px作为设计目标 | 静态样式值不等于最终热区；需设备/布局检查 |
| 状态 | 适用的空/加载/错误/禁用/成功状态、清楚恢复方法；键盘/读屏标签 | 实际路径，模拟失败只能算模拟验证 |
| 响应与可读 | 窄/标准/大尺寸、长中文、字体放大、键盘遮挡、安全区 | 目标环境截图/交互，不默认 390px 证明真机 |
| 代码与行为 | 控件是真实组件、关键流程连通、已有功能无回退 | 启动、操作路径、必要测试；构建成功不足以验收 |
| 编辑器交接 | 文本/布局/组件/矢量独立、字体可用、一次真实编辑 | 文件/节点链接、对象树与编辑结果；PNG 不算可编辑 UI |
| 宣传交付 | 真实产品屏幕、可证实文案、主要行动目的地、渠道尺寸与裁切 | 页面最终渲染与实际链接；海报导出；平台规格来源。制作不等于上线/投放 |

默认先修阻碍主要任务、可读性与结构的问题，再修细节。迭代轮数随证据和资源决定；进入同一问题的重复失败时检查目标、素材、实现约束，不只重写同一句提示词。

交付状态分层：

- `verified`：当前任务实际执行，附证据和验证范围。
- `partial`：有可用成果但目标仍有已知缺口。
- `not_executed`：没有运行该阶段，不能标通过。
- `needs_input`：依赖具体素材、平台/设计目标或新增授权；描述最小缺口。

`assets/delivery-template.json` 用于记录，文件存在不证明内容真实。`studio.py check` 只检查字段、状态与本地证据路径，返回 `artifact_contract_valid`；即使通过也不会将 `ui_quality_verified` 置为 true。远程图层与真机需独立查看。

SaaS 模式可改用 `assets/saas-delivery-template.json`，把 delivery.json 放在本次交付的项目根目录，以该根目录的相对路径记录素材、接入组件和证据。`requested_creative_providers` 表示本次任务要求的 provider，不代表费用授权；按真实需求调整。用户要求两工具参与时，Lovart 和 image 各有独立 creative_runs；任一仅有提示词、pending 或未接入产物时不能标记双方 verified。脚本只检查结构与非空文件，实际工具回执、图像内容、组件引用和最终渲染仍由执行者查看验证。

需要 Figma 或其他编辑器时：先给本地交接包；核对可用连接和用户指定目标；按工具规范转换；验证对象树与一次修改；保存链接和实证。不可用时明确留下转换缺口，现有本地成果保持可用。不要因账户保存成功、HTTP 200、设计工具已安装就跳过这一步。
