# 可填充提示词模板

以下为原创参数化模板。把方括号替换成当前项目事实，未知标 unknown；它们不是必须每次全部运行的固定流水线。

## A. 品牌定义

基于附件中的 [logo]、[IP/吉祥物]、[产品资料] 为 [产品名称] 定义 APP 的品牌视觉。用户为 [人群]，主要场景是 [场景]，首要任务是 [任务]。保留 [不可改元素]，气质为 [3个有取舍的词]。给出色彩角色与可访问配色、中文/英文字体与字阶、间距与圆角、图标体系、素材处理、动效原则及明确不采用的视觉习惯。用 [需要的页面] 验证这些原则如何落地。已有品牌规范优先；不要复制其他品牌的标志或私有素材。输出既能看懂也能转成代码 tokens 的规格。

## B. 多屏界面视觉

使用 [品牌规格/附件] 与 [风格参考图] 设计 [平台] APP 的 [屏幕列表]。每屏以 [该屏任务] 决定信息层级和主动作。锁定同一组颜色、字体、间距、图标、导航和 IP 比例；不得每屏随机换样式。画布为 [尺寸与单位]，考虑顶部/底部安全区；文本为 [语言与真实文案]。同时写出每屏的交互意图与 [空/加载/错误等必要状态]。图像只作为视觉方案，后续用组件实现可交互界面。不要以密集海报文字代替可读界面。

## C. 吉祥物或插画素材

以 [可用的IP参考图] 为身份与造型依据，为 [素材用途] 生成独立素材。保持 [轮廓、比例、面部特征、材质、光向] 一致，只变化 [姿势/情绪]。目标尺寸 [尺寸]，透明背景，边缘干净，不带棋盘格、文案、控件、品牌外水印。输出逐项命名 [文件名列表]，留足边距。不得借不存在的参考图声称身份一致；需查看输出 alpha。只有工具支持且便于后续拆分时才批量生成，不默认雪碧图一定更快。

## D. 从图还原交互代码

先分析 [参考图] 的布局、尺寸比例、字阶、间距、圆角、素材层级与组件状态，结合 [项目实际栈] 实现 [屏幕/流程]。保留 [路由、业务数据、已有品牌]。文字、按钮、列表、输入和导航使用真实组件；吉祥物等插画用独立素材 [文件列表]。实现适用的点击/按下、焦点、禁用、加载、验证失败与返回路径；触屏不依赖 hover。图像文字若出错，以 [产品文案] 为准。运行后在 [目标尺寸] 截图比对并修复最大差异，交付启动入口、已验证交互与尚未接通的服务。不要把整屏图片当成界面实现。

## E. 有证据的纠偏

参考图为 [文件]，当前实际截图为 [文件与尺寸]。本轮只处理已观察到的 [结构/比例/字阶/素材/交互问题]，保留 [已确认部分]。按影响从大到小列差异，再修改对应组件；同尺寸重新截图并实际操作 [关键路径]。逐项报告改前/改后与仍存在的偏差，不以主观“更高级”代替证据，不为追求相似破坏可访问性与真实功能。

## F. 可编辑设计交接

把 [已运行页面/组件] 交接到 [用户选定编辑器]。保留文本为文本，导航/按钮/列表为独立组件，吉祥物为图片素材，复用 [tokens]。先验证当前工具是否支持所需导入，不支持则交付本地源码、assets、tokens、组件映射和导入步骤。转换后核对图层树、字体替换、Auto Layout/等效约束，并验证修改一次按钮文案/间距的实际结果。只贴入整屏图片时标为图片预览，不能称为可编辑 UI 已完成。

## G. 宣传页 / 主视觉

为 [产品] 制作 [落地页/海报/商店截图]，目标用户 [受众] 在 [场景] 需要 [真实任务]，核心价值为 [可证实的承诺]，主要行动是 [已知目的地/待配置目标]。保留 [品牌规范、tokens、IP与真实APP截图]，画幅/响应尺寸为 [渠道规格或明确的草稿假设]。按 [内容顺序] 组织信息，首屏用 [真实产品画面/独立主视觉] 说明产品，给 [主标题与行动按钮] 留出可读空间。使用 Lovart 或 image 时按当前可用工具规则处理参考图；网页文字和控件由真实代码实现。不要编造评分、评价、销量或不存在的功能。交付 [代码/导出图片/源文件]、最终渲染和已验证行动路径；未接通服务、未核对平台规格和未部署分别标明。
