# 文案、术语与可审查交接

copy、terminology、review-context、readme、handoff使用本文件对应部分。来源见 [oil-ecosystem.md](oil-ecosystem.md)，不自动调用上游个人风格或发布工具。

## 写清动作、对象与结果

先保留事实、数字、否定、限制和承诺，再按读者顺序组织表达。删没有信息的口号、机械转场与总结，补齐确实缺失的因果和操作关系；自然不等于机械改短句。标题说明实际对象，按钮说明动作，错误说明原因与恢复，不能把产品状态、权限或商业承诺改掉。

只润色时保持原有观点和材料边界，不编造第一人称经历、用户反馈或“已提升”结论，也不模仿上游作者身份。界面文案在实际宽度和语言环境里核对截断、长文本与错误关联。

## 术语帮助表达，不扩大需求

把口语先转换成可观察的行为；确有帮助时解释最相关概念，不因编程任务就附术语课。歧义会改变业务时再澄清，能推断的低风险细节标假设继续。提供词条链接需查询并核对实际返回地址，不自行拼接VibeHub内链。

查询只发送脱敏短术语，不发送源码、私有地址、密钥、账户或个人路径；没有查询能力时照常解释和开发，标清链接未核验。用户已说准确就直接完成任务。

## 批注要有位置和版本

每条反馈绑定到文件/行，或路由、视口、状态及截图区域；分开原话、观察、推测、建议和实际修改。保留前后版本与来源引用，使用本轮已确认的证据，不能从相似目录取图充当当前结果。

多文件画布只有当前任务需要时才用；优先现有载体或本插件board，不自动安装Mira、注入Selector或扩大外发范围。上下文应足以让协作者独立定位，而不是堆所有文件。只说明Git变化时读取指定范围，按用户行为组织变更，不顺带提交、重置或清理工作区。

本地Git查看可分当前分支、工作树差异和提交历史，但只读结果不能被说成提交/推送成功；外部查看器也以当前真实仓库为准。关系多、宽表或版本对照确实难读时，选择能显示关系与证据的HTML表达；先组织内容，再决定表格、关系图和少量交互，不移植上游固定主题。

每条截图意见独立绑定候选ID、屏幕ID、视口尺寸、文件引用、SHA-256和位置；图片上的位置用原图归一化坐标，避免换显示比例后漂移。切换查看对象或推荐方案不改变已有意见的归属。交接同时带可阅读文本和需要的结构化文件；执行回改前核对实际截图字节，指纹不符就重新定位，不能把旧位置套到新画面。

本插件board支持点击或键盘百分比定位、本标签页草稿与JSON导出。用 `python3 "<技能目录>/scripts/studio.py" board-feedback board/board.json feedback.json` 只读核验截图身份和意见结构；通过仅证明交接文件对应当前截图，不证明建议正确或已经回改。完整格式与实际操作见 [comparison.md](comparison.md)。

## README与交接格式由目标决定

README先让读者知道项目做什么、实际产物、最短运行路径、环境前提和边界；命令与入口应核对当前仓库，真实截图、示意图与未执行项标清。只要图形资产时不改整份README，动图没有信息价值就不增加。

滚动HTML适合查阅，翻页演示适合讲述，文章适合连贯阅读；用户没要求不同时生成所有格式。每页或章节先明确一个判断，再用合适的真实截图、图表或关系图说明，不强制等权卡片、固定配色或多余总结页。

导出后核对资源、字体、裁切、离线打开与目标尺寸。可编辑交付须验证独立文本/图层和一次实际编辑；屏幕图片不能替代工程或可编辑设计。视频转文章时检查字幕、剪辑时间轴与选帧对应关系，不靠猜画面写事实。
