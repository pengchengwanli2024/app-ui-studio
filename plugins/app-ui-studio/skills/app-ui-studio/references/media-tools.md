# Lovart / image 图像协作

本插件编排宿主已提供的工具，不内置图像模型、账号、密钥或新 MCP 服务。不写死工具命名空间、账户 ID、模型版本或计费信息。先看当前工具描述；必要时加载该提供方技能，遵循其当前规范。这里的接口名称用于能力映射，实际调用必须使用本会话的真实 schema。

## 选择与准备

1. 从真实任务列素材：UI 方向图、品牌板、独立 IP/插画、宣传主视觉、背景；区分现有可用素材与需要生成的素材。保留用户授权的品牌和参考，不把文章示例 IP 当成自有素材。
2. 用户指定 Lovart 时优先 Lovart；指定 image / ChatGPT 图像时用宿主图像工具。未指定时，用已有能力满足本次目标：需要延续 Lovart 项目与参考图管理时选 Lovart，单张方向或透明素材可选 image。已有产物够用就直接复用，不默认两边各跑一遍。
3. 使用用户已明确的账户/项目。Lovart 暴露多个可用账户且目标不明时，先完成 brief 和提示词，再按工具要求只询问账户选择；不能自行猜测。工具会消耗配额时沿用当前授权与预算，不启动无界多版本生成，不因配额不足推荐升级购买。
4. 提示词至少含：用途、受众、画布比例、品牌锁定项、参考角色、构图、文案/留白、独立素材和验收点。默认先生成一个方向，是否增加由实际差距和授权决定。敏感内容和未获准上传的素材不外发。

## 两工具参与与素材落地契约

用户明确要求 Lovart 和图像工具都参与时，分别制定产物而非把两者视为替代名词：Lovart 可负责 UI 视觉方向、品牌视觉或宣传 KV；宿主图像工具可负责独立插画、透明 IP、局部编辑或同一方向的可复用素材。按任务分配，已有素材足够时不重复收费生成；若请求仅为不涉及素材的局部 UX 修复，记录不需要生成的理由。

每个请求的产物按下列链路推进，当前阶段缺证据时保持 partial / not_executed / needs_input：

先区分本轮生成与沿用产物。复用的身份素材保留原有来源与哈希，不为凑provider数重复生成；新生成的方向稿可接入清楚标注的比较/交接页面，不能拿它当可操作APP。各项输出按真实用途记录，不把“方向参考已查看”写成“产品组件已还原”。

1. **计划**：记录 provider、用途、参考、品牌锁定项、目标尺寸/比例、透明需求与组件落点。
2. **生成**：实际调用当前工具 schema；记录真实 task / project / artifact 标识和完成状态。pending 不能进入已完成清单。
3. **查看**：用提供方原生展示或可用预览实际看图，核对身份、比例、文案与品牌；URL 和评分不能替代看图。
4. **落地**：将可用产物保存至当前项目约定的素材目录，或采用项目允许且可访问的托管资源。遵循宿主展示规则，不为了绕过展示限制下载；本地项目需要素材时可按授权保存，并保留来源。不得向插件包写用户项目图片、凭据或账号配置。
5. **接入**：明确素材被哪个组件/路由使用，补齐尺寸、替代文本、裁切和加载策略。生成的整屏概念图只作参考；文字和控件仍由真实组件构建。
6. **验证**：查看最终渲染，检查素材裁切、文字覆盖、跨屏一致性与相关交互；按需要做 alpha、暗色与减少动态效果检查。

SaaS 项目可使用 `assets/saas-delivery-template.json` 的 creative_runs 记录两条独立链路。两个 provider 中有一个未执行时分别如实报告，不能写成“两工具均已参与”。`studio.py check` 只检查这些声明及本地文件契约，不验证工具来源、图片真实性、接入语义或视觉质量。

## image 路径

- 直接使用宿主图像生成/编辑工具及当前接口。新图不传无关参考；编辑时包含全部目标图，先查看尚未看过的本地参考。
- 用户要求透明背景时设置工具的透明背景选项；有透明原图的编辑默认保留透明。不能用棋盘格图冒充 alpha。
- 先把品牌、IP 身份和跨屏共用约束写清；生成图不保证文字准确，代码中使用真实文本，营销素材检查文字后再交付。
- 按宿主规范展示原生生成结果；工具返回本地路径时可用本地预览。不能凭路径或 URL 就宣称已看图。

## Lovart 路径

- 使用当前 `generate_image` 或 `edit_image`；一般保留默认模型，仅在用户指定或能力有缺口时查询 `list_models` / `describe_model`，不猜参数。
- 外部参考图按当前 `upload_asset` 规范先进入 Lovart 存储；已是 Lovart 托管的 URL 可直接用。不得把本地路径或未获授权的外链直接塞进参考字段，也不在插件内保存账号 ID。
- 复用返回的 `project_id`，不每次创建空项目。把 `task_ids`、状态、实际错误和产物保存到当前项目的最小任务记录，不记录凭据或无关账户数据。
- 异步生成按实际 `poll_after_seconds` 与宿主规范处理。当前工具若要求用 `get_task` 汇总展示，则一次提交本轮任务 ID；需要等待依赖时用 `get_task_status`。不要把 pending 当成 completed 或重复提交同一请求。
- 质量判断时取得可见预览（例如工具支持的 `include_images`），核对真实输出。模型评分或排名只是辅助，不能代替产品任务和人工可见检查。分层或矢量化若需要，另按工具能力与授权执行；拆开的图片层不自动等于可编辑文字和 UI 组件。

## 检查与失败处理

查看真实图片并核对品牌、版式、比例、IP 形状、主要文字与边缘。需要 alpha 时检查文件透明通道；无法检查时写清未核验。记录实际工具、引用素材、输出路径/链接、已观察差异和修正结果。

无工具、认证/额度不足、生成失败时保留错误摘要；该阶段标 `not_executed`、`partial` 或 `needs_input`，交付填好事实的提示词和素材清单，继续不依赖生成图的布局/代码工作。不得伪造图片、后台任务、通知或成功回执。生成图、可交互界面、可编辑设计和原生设备验收分别报告。
