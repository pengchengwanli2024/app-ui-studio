# SaaS 制作提示词

复制下面整段，替换方括号；未填写的非关键项可由项目事实推断并注明。

```text
$app-ui-studio saas

请在真实项目中完成以下 SaaS 设计与实现，并按实际证据交付。

项目目录：[绝对路径；尚无项目则写“新建于……”]
平台：[桌面 Web / 移动 Web / 原生平台 / 跨平台；填实际目标]
scope：[new / existing / mixed]
tone：[tech-refined / calm / tech-expressive；默认 tech-refined]
产品、用户与主要任务：[真实产品背景、使用者、最重要的操作]
本次页面与范围：[页面、路由、Operate 工作台 / Persuade 营销页、交付边界]
已有规范与需保留内容：[需求、设计系统、品牌、参考、数据接口、已确认结构；填路径或链接]
视觉与素材需求：[UI 视觉 / 品牌素材 / 宣传 KV 的用途、参考及已有素材；无则按实际需求制定]
交付物：[代码 / 可交互原型 / 可编辑设计 / 其他]
运行与验收：[项目命令、目标尺寸/设备、必须验证的关键路径]
工具与费用授权：[允许使用的工具、允许外发的素材、额度/费用上限；未授权额外付费则明确写出]

执行要求：
1. 先读取适用项目规范与现状，确认 scope，保留已有技术栈与用户工作。只补问实质阻碍交付的缺口；低影响缺口说明假设后继续。不得默认生成通用 SaaS 仪表盘或添加无需求的页面。
2. 读取 SaaS 模式与四技能集成规则。实际可用时让 UI/UX Pro Max、Mobile App Design、Taste、Impeccable 按各自完整职责共同推进；记录缺失能力。Taste 要参与布局、密度和视觉实现；已确认的结构不能在精修中偷偷更改。
3. 先锁定用户任务、信息层级、共享 tokens 与 asset plan。Operate 注重长时阅读、任务效率与状态；Persuade 可加强品牌表达与价值叙述，两者共用语义和品牌 tokens。不要把科技感等同于暗色或满屏装饰。
4. 若我要求科技表达，将空间层次、品牌光场、语义数据流、细致反馈、局部 3D/粒子落实到明确表面与目的。此方向优先于通用去装饰偏好，同时满足平台惯例、对比度、reduced motion 和实际性能要求。
5. 对所需 UI 视觉、品牌素材和宣传 KV，读取 media-tools.md，按实际能力让 Lovart 与当前图像工具参与制作。执行“UX/tokens/asset plan → 实际生成 → 筛选下载并保存到项目可用位置 → 真实组件接入 → 渲染/对比/交互验证”，不能只口头提及工具。遵守上述素材与费用授权；不能执行的步骤标 not_executed，并继续不依赖图片的部分。
6. 文字、按钮、导航、表单、列表与业务状态使用真实组件，不用整屏图片替代 UI。实现适用的加载、空、错误、焦点和禁用状态，连接本次要求的真实使用路径。
7. 不编造客户、评价、认证、营收、实时 agent 数、产品能力或线上成功记录；必要示例明确标记。没有证据的商业背书留待真实内容，不以假案例补齐。
8. 在目标尺寸/设备进行实际渲染、视觉对比与关键路径操作，修复有证据的问题。最终交付入口、素材路径与组件映射、运行方式、验证证据和剩余差距，区分 verified / partial / not_executed / needs_input；不能把计划或提示词写成已完成成果。
```

仅制作提示词时，把第一句改为“请只交付适用于以下真实项目的 SaaS 制作提示词，不修改项目，不生成素材或产生费用”，并保留其余项目输入与约束。
