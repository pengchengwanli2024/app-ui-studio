# APP UI Studio 1.3 compare evidence contract

Implement `compare BASELINE_JSON CANDIDATE_JSON [--output NEW_REPORT_JSON]` in the selected studio.py using stdlib only, preserving old doctor/contrast/init/preset/check behavior. Source and all harness inputs are read-only. Deliver only a unified `fix.patch` targeting `a/plugins/app-ui-studio/skills/app-ui-studio/scripts/studio.py` -> `b/.../studio.py`, and `trajectory.md`. Apply work to disposable copies. No network, UI generation, publishing or global writes.

Each input manifest is a JSON object with schema_version strictly integer 1 (not bool); product and plugin_version nonempty strings; plugin_manifest a project-relative JSON path whose object.version exactly matches plugin_version; capture_context a nonempty JSON object; business_files and brand_assets nonempty lists of unique nonempty relative file paths; screens a nonempty list of objects {id:nonempty unique string, artifact:relative PNG/JPEG path, viewport:{width:positive integer, height:positive integer}}. Booleans are not integers. All references are relative to the corresponding input manifest's parent. Reject absolute paths (including Windows-style absolute paths), any .. component, symlink escapes, missing/nonregular/empty files, invalid JSON (including duplicate keys and nonfinite JSON constants), malformed image headers and actual-versus-declared dimensions mismatch. PNG/JPEG dimensions must be read from actual image bytes using stdlib; no Pillow or extension-only validation. Image authenticity is not established. Files referenced by each manifest must stay inside its root, and no arbitrary outside file may be read. Internal symlinks may be accepted if their resolved target stays inside the root. Initial manifest arguments themselves are explicit user-selected files and may be absolute. Referenced plugin manifest must be JSON object with matching nonempty version. Preserve all input bytes.

Comparison permits different plugin versions. Valid evidence is comparable only when product, capture_context, business file relative keys and SHA256 bytes, brand asset keys and SHA256 bytes, and screen ID sets and viewports match. Screen ordering is not material; screenshot artifact names and image bytes may differ; report per-screen changed true/false by actual SHA256. Changes to business or brand relative keys are not comparable even if bytes match. A malformed input is invalid, not merely not-comparable. Validate both sides before returning valid/not-comparable.

All compare outcomes (including missing arguments/invalid options) emit one parseable JSON object to stdout, no traceback. Always include comparison_contract_valid boolean, comparable boolean, visual_quality_verified=false, screens list, limits (nonempty string or list). For valid inputs also include baseline_version and candidate_version string, differences list. Screens entries identify id, baseline/candidate evidence as useful, and changed boolean when both sides exist. Invalid outcomes include errors. Exit0 = valid and comparable; exit1 = valid but not comparable; exit2 = invalid input/output or format/CLI error. `--help` may retain conventional text/exit0. No visual score or claim of better quality.

Without --output do not write any file. With --output exclusively create one new JSON report only after validation; refuse any existing path, including files/directories/symlinks/broken symlinks/inputs, and do not overwrite or truncate. Do not create missing output parents. File JSON must equal stdout JSON. Invalid inputs may simply report to stdout and avoid writing. On output failure return JSON exit2 with contract false. Inputs and user files must be preserved.

The frozen probe generates isolated fixtures and tests the public contract. The independent validation has additional boundaries; do not inspect it to tailor a patch. Probe is not browser/design-quality acceptance. Run `python3 qa/harness/check.py`; record actual commands/exits and limits. No nested Harness², no other candidates/results access.
